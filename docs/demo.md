# Two-to-three-minute demo

This path presents the actual local application using fictional Riverton identities. Start with `npm run dev`, open http://127.0.0.1:3000, and use the synthetic identity selector. For a repeatable starting point, use coordinator Naila's Settings → Reset demo data → Confirm reset, then select Mira. Reset replaces synthetic local records; do not use it to retain a previous demonstration.

1. **0:00–0:25 — The everyday network.** Show the homepage, enter the community workspace as Mira, and choose Ask for help. Use the everyday groceries example, review the provisional fields, then create the request. Explain that raw intake is private and matching is a suggestion.
2. **0:25–1:15 — Agreement and real follow-through.** Invite Eli from Possible connections. Select Eli's demo identity, open the invitation through My activity and choose Agree to connect. Private coordination now opens. Choose Start helping, then Report delivered. Select Mira again and choose Confirm help received. Only requester confirmation counts as a successful outcome; multi-need requests track each need separately.
3. **1:15–1:45 — Coordinators step in when needed.** Select Naila and open Coordinator. Filter Needs attention to show follow-up flags. Open a private case to show the review boundary. Administrative closure and referral are separate outcomes from confirmed help.
4. **1:45–2:45 — The same network during an incident.** In Coordinator, choose Flood and Activate simulation. Open Resources to show that existing organizations must confirm readiness for this incident. Select the Maple Mobility organization identity, save capacity/reaffirm, then Confirm incident readiness. Show the updated stored capacity and current incident readiness, then return to Naila. These are the same organization records used in everyday mode; no alert or dispatch is sent.

For a longer demonstration, use Intake studio to paste the flood example, review its provisional categories, save the private case and Record review as Naila. Before incident readiness is reaffirmed, the relevant resource is excluded; afterward the eligible suggestion appears. Classification is editable: the word “water” can also suggest Supplies, so remove that category if it does not describe the intended request. Return to everyday mode when finished.

All identities, qualification labels, resource capacity, events and demo time are synthetic. Optional Ollama and hosted model adapters require a separately configured service. The demonstrated path works with the deterministic provider and no API key. See [feature status](feature-status.md) for the verification limits.
