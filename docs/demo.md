# Two-to-three-minute demo

Use fictional Riverton identities and the deterministic provider. Start with `npm run dev`, open http://127.0.0.1:3000 and choose **Enter demo**. The identity selector switches fictional people. For a clean presentation, Naila can use **Settings → Reset demo data → Confirm reset**; this discards changes in that demo database.

1. **0:00–0:35: Ask in everyday language.** As Mira, open **Ask for help**, enter “I need groceries near Central Park”, then choose **Help organize this request**. Review the category and neighborhood, select **Now**, confirm the exact displayed window and create the request. Show its case reference and explain that the original intake remains private.
2. **0:35–1:35: Connect and confirm.** Invite Eli from the suggested matches. Switch to Eli, open the request through **My activity**, agree to connect, start helping and report delivery. Switch to Mira and confirm help received. Private coordination opens after mutual agreement; the helper cannot confirm their own delivery.
3. **1:35–2:15: Adapt the same network.** As Naila, activate the Flood simulation in **Coordinator**. Open **Intake studio**, select **Simulated flood transcript**, analyze it, choose and confirm the time window, then create the request. The incident-linked case stays private and requires review. Record review from the case controls.
4. **2:15–3:00: Show resources and unresolved work.** Switch to Maple Mobility Partners, open **Resources**, edit the accessible transportation listing and save it as ready for the current incident. Return to Naila and open **Emergency**. Show available/unavailable resources, shelter and transport partners, the review queue and the newly linked request. Its unresolved needs remain visible until actual consent, assistance and requester confirmation occur; no alert or dispatch is sent.

For an additional feature tour, compare **Needs helper** with **No coordinator owner**, filter by a helper, open **Organization applications**, or schedule dated offers in two neighborhoods. **Settings** shows the automatic follow-up runner; advance the simulated clock to make conditions due. Member incident actions lead to their own offers, and organization actions lead to resource readiness. Return to everyday mode after the incident demonstration.

Account recovery has a separate local operator walkthrough in [the deployment guide](deployment.md). All demo people, qualifications, resources and outcomes are synthetic. Optional models need a configured service; the fallback needs no key. See [feature status](feature-status.md) for verified behavior and remaining gaps.

For the newer community workflows, visit **Gatherings** to create an activity and join or leave up to its capacity; the organizer or coordinator can cancel it. In **Volunteers**, a member can publish or hide an opt-in profile with ordinary capabilities, general areas and languages. In **Offers**, an owner can add a self-described organization affiliation; it does not verify membership or change matching eligibility. In **Intake drafts**, save a request with missing location or time, review the private draft, then resume the regular analyzed and reviewed request flow. A draft remains private and out of matching until the author creates and links the request.

Other optional tours: switch to Spanish for translated core interface controls, use the speech button to append dictated text to the editable intake draft, open **Neighborhoods** to select and zoom the illustrative Chicago map, or compare the redesigned everyday and disaster-management themes. From the disaster hub, coordinators can open a private people report, ask a question for its author, review replies and status history, and optionally share a redacted notice with the community. Members can add their own check-in name or submit a private tip; neither is a public search or dispatch. An adult may separately authorize use of their name, and revoking that consent removes it. Administrative closure does not establish reunification. A local Ollama setup can be checked with `npm run check:live-ai -- http://127.0.0.1:3004`; only the tested fictional input/model path is verified. The three disaster screens currently fall back to English; dictation does not submit or analyze automatically, and user or model text is not translated.
