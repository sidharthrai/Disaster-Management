# Deployment safety fix report

- Demo reset rejects non-demo APP_MODE before opening SQLite, and checks existing dataset settings and every user inside an immediate transaction before replacing data. Unknown, mixed, and live datasets are rejected. A new demo database can still be seeded.
- `scripts/account-role.mjs` is a Node-only operator tool using the production SQLite dependency. It requires account mode, an existing live dataset, and a mapped non-synthetic account. It updates only the selected user JSON in an immediate transaction, preserving unrelated fields. Organization verification requires `--verify`; organization qualifications are explicit category arguments, separate from verification. Changing to a non-organization role clears verification and qualifications. Unknown roles, categories, and inappropriate arguments are rejected.
- Role or qualification changes preserve historical resource and commitment links. They do not automatically revoke or reconcile existing resources or commitments; operators must review and handle these after deprovisioning. Existing active medical resources in particular need review when medical qualification is removed.
- Runtime database paths are resolved with Node's URL/path conversion at runtime instead of a dynamic `path.resolve(process.cwd(), ...)` tracing expression. Configurable absolute paths remain supported, including paths with spaces and `#`. The production build emitted no broad project-tracing warning, and an inventory of `.next/standalone` found no `*.sqlite*` or `.env*` files.
- In account mode, mutation origin checks use validated `APP_BASE_URL`, allowing an HTTPS browser origin behind an internal HTTP reverse proxy without trusting forwarded headers. Demo mode retains incoming-host behavior.
- Verification: `npm run typecheck` passed; focused deployment and HTTP tests passed (7 tests). A production build succeeded. The actual packaged standalone Node CLI updated an isolated temporary live fixture successfully, including a path with spaces and `#`. No live database was used. Docker is unavailable, so no container image execution was performed.
