# Private intake drafts

The private inbox at `/intake-drafts` lists drafts authored by the current actor and, for coordinators, drafts in their community. A draft stores the message and source without requiring a neighborhood or time. It does not create a request or enter matching. The author can edit, withdraw, resume through `/request?draftId=...`, or link an already-created owned request. A coordinator may record a bounded information request visible to the author. Withdrawn and converted drafts are terminal.

`GET /api/intake-drafts` returns `{ drafts: IntakeDraft[] }` for the authorized actor. `POST /api/intake-drafts` accepts strict JSON commands: `{ action: 'create', input: { text, source } }`, `{ action: 'update', id, input: { text, source } }`, `{ action: 'request_information', id, note }`, `{ action: 'withdraw', id }`, and `{ action: 'convert', id, requestId }`. Successful mutations return `{ draft: IntakeDraft }`. The route uses same-origin mutation checks, bounded JSON bodies, private no-store headers and runtime validation. Text is trimmed and limited to 8–6000 characters; notes are trimmed and limited to 1–1000 characters. Conversion checks the request belongs to the author and community, and a request cannot be linked to two drafts.

The normal analyzed and reviewed request flow remains responsible for request creation. A local guard spans request creation, draft linking and navigation and retains the returned request reference to prevent another submission. If linking fails, the client identifies the created request and directs the author to link it from the inbox without creating another request. Draft loading is limited to the author and will not overwrite edits made while loading or after an identity change. The shared command wrapper retains a successful mutation result if the subsequent snapshot refresh fails, and displays a refresh warning rather than reporting the mutation as failed.

Verification: `npx vitest run tests/intake-drafts.test.ts tests/command-result.test.ts` covers private visibility, cross-community and nonauthor rejection, information requests, updating, ownership on conversion, history, validation, terminal states, and the distinction between mutation and refresh failures. `npm run typecheck` checks the integration. Browser and live HTTP checks were not run within this worker's assigned scope.
