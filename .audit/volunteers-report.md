# Volunteer directory report

The `/volunteers` page lists only member profiles explicitly published in the current community. Members can save or hide their own profile; account role and community are checked against current records. The API uses the authenticated session, private response headers, same-origin mutation checks and bounded input. Profile fields are limited to ordinary categories, general areas, languages and visibility; display names come from current accounts. No contact information or free text is accepted. Existing records with sensitive categories are projected without those categories.

`GET /api/volunteers` returns `{ ownProfile, volunteers }`; `ownProfile` is null for non-members or absent profiles, and each published card contains `id`, `name`, `categories`, `areas`, `languages`, and `eligibleOfferCount`. `PUT /api/volunteers` accepts the strict profile object `{ categories, areas, languages, visible }` and returns `{ ok: true }`. Offer counts include active offers with a valid current or future window, an ordinary category, and, during an incident, readiness for that incident. They do not represent a guarantee of availability or matching eligibility for a particular request. Cards link to `/request` with an ordinary category and area when both are available; requests continue through existing matching and mutual consent.

Verification: `npx vitest run tests/volunteers.test.ts` passed two tests covering publication, hiding, role and community isolation, input restrictions, offer windows and incident readiness, and private data projection. `npm run typecheck` passed after the separately owned gatherings errors were corrected. No build, server, browser, dependency installation, deployment, or Git action was performed. Live interaction and combined integration remain for the coordinating agent.
