# Group activities implementation

The `/gatherings` page creates fixed-kind neighborhood activities and supports joining, leaving, and organizer/coordinator cancellation. Creation records an empty attendance list, so organizers join explicitly and count normally. Inputs use a future offset from the application clock and a fixed duration, with Central-time previews. Notes and participant names are available only to the organizer and same-community coordinators; other members receive counts and their own attendance status.

`GET /api/gatherings` returns the validated projection. `POST /api/gatherings` accepts `{ action: 'create', input: { kind, area, startAt, endAt, capacity, notes } }` or `{ action: 'join' | 'leave' | 'cancel', id }`, and returns `{ ok: true }`. Requests require the current server identity and same-origin JSON for mutations. Each mutation rechecks membership, community and authorization inside the SQLite transaction; participation cannot be duplicated or exceed capacity, joining requires an unexpired window, and cancellation preserves attendance history while blocking participation changes.

Verification: `npx vitest run tests/gatherings.test.ts` passed (2 tests); `npm run typecheck` passed. The focused tests exercise actual SQLite transactions, capacity, duplicate joins, leaving, cancellation, private projections, community isolation, invalid inputs, and expiry. HTTP and browser integration were assigned to the parent and were not run here; concurrent process contention was not separately stress-tested. No production build, server, Git, browser, or dependencies were used.
